> Izpildlaika slēdži, kas maina OmniRoute darbību **bez atkārtotas izvietošanas**.
> Katrs šeit norādītais karogs ir definēts failā
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — vienīgajā patiesības avotā. Gan informācijas panelis, gan REST API nolasa datus no
> šī faila, tāpēc tālāk redzamā tabula ir ģenerēta, lai tam precīzi atbilstu attiecībā 1:1.

---

## Kas ir funkciju karogi

Funkcijas karogs ir nosaukts slēdzis (Būla vērtība vai uzskaitījums), kura vērtību var mainīt
izpildlaikā un saglabāt datubāzē bez nepieciešamības atkārtoti izvietot procesu. Katru
karogu apraksta `FeatureFlagDefinition` ar `key`, `label`,
`description`, `category`, `defaultValue`, `type` un `requiresRestart` norādi.

### Izšķiršanas secība

Karoga **efektīvo vērtību** nosaka
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts), izmantojot šādu
prioritāšu secību (augstākā prioritāte uzvar):

1. **DB pārrakstīšana** — vērtība, kas saglabāta tabulā `key_value` zem
   nosaukumvietas `feature_flags` (iestatīta, izmantojot informācijas paneli vai REST API).
2. **Vides mainīgais** — `process.env[<KEY>]`, ja tas ir iestatīts un nav tukšs.
3. **Definīcijas noklusējums** — `defaultValue` no `featureFlagDefinitions.ts`.

Būla karogs tiek uzskatīts par **iespējotu**, ja tā efektīvā vērtība ir `"true"`,
`"1"` vai `"yes"` (skatiet `isFeatureFlagEnabled()`).

> [!NOTE]
> Vairumam karogu ir arī atbilstošs vides mainīgais ar **tādu pašu nosaukumu**,
> kas dokumentēts failā [`ENVIRONMENT.md`](./ENVIRONMENT.md). Karoga DB pārrakstīšanai
> ir augstāka prioritāte nekā šim vides mainīgajam. Karogs ar
> `requiresRestart: true` tiek saglabāts nekavējoties, taču tiek atkārtoti nolasīts tikai procesa
> palaišanas laikā — tā pārslēgšana informācijas panelī parāda reklāmkarogu **"Restartēt serveri"**.

## Karodziņu pārslēgšana

### Informācijas panelis

Dodieties uz **Informācijas panelis → Iestatījumi → Funkciju karodziņi**
(`/dashboard/settings/feature-flags`). Režģis
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) atbalsta:

- **Meklēšanu** pēc atslēgas vai apraksta, un **filtrēšanu** pēc kategorijas (plus sintētisku
  **Nepieciešama restartēšana** skatu).
- **Pārslēdzēju** Būla karodziņiem un **nolaižamo izvēlni** uzskaitījuma karodziņiem
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Avota emblēmu** katram karodziņam — `DB`, `ENV` vai `DEF` — kas parāda, no kurienes
  nāk efektīvā vērtība.
- **Atiestatīšanas** pogu (redzama tikai `DB` avota karodziņiem), lai atceltu ignorēšanu,
  un pogu **Atiestatīt visas ignorēšanas** apakšā.
- **Restartēt serveri** reklāmkarogu, kad tiek mainīts `requiresRestart` karodziņš.

### REST API

Visas darbības notiek caur vienu maršrutu:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Katram metodēm nepieciešama autentificēta informācijas paneļa sesija (`401` pretējā gadījumā).

#### `GET /api/settings/feature-flags`

Atgriež katru karodziņu ar tā efektīvo vērtību, avotu un kopsavilkumu.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... visi 77 karodziņi
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Iestata vai noņem vienu ignorēšanu. Pamatteksts: `{ key: string; value?: string }`.
Izlaižot `value`, tiek noņemta ignorēšana (atjaunojot vides / noklusējuma vērtību).

```bash
# Iestatīt DB ignorēšanu
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Noņemt ignorēšanu (bez "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Atbilde atspoguļo jauno `effectiveValue`/`source`, `previousValue`/
`previousSource` un `requiresRestart`. Nezināmas atslēgas un ārpus diapazona
uzskaitījuma vērtības tiek noraidītas ar `400`.

#### `DELETE /api/settings/feature-flags`

Notīra **visas** DB ignorēšanas uzreiz, atjaunojot katru karodziņu uz tā vides /
noklusējuma vērtību. Atgriež `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Karodziņi ar `requiresRestart: true` stājas spēkā tikai pēc procesa pārlādēšanas.
> Informācijas paneļa restartēšanas plūsma izsauc `POST /api/restart` un pēc tam
> aptaujā `GET /api/health/ping`, līdz serveris atkal ir tiešsaistē.

## Ārkārtas budžeta rezerves mehānisms

`OMNIROUTE_EMERGENCY_FALLBACK` (kategorija `runtime`, noklusējuma vērtība `true`) kontrolē
ārkārtas bezmaksas rezerves maršrutēšanas ceļu failā
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Kad tas ir iespējots, pieprasījumi, kuru budžets ir izsmelts, tiek maršrutēti uz bezmaksas rezerves
nodrošinātāju/modeli, nevis uzreiz noraidīti. Iestatiet to uz `false` (vai `0`) — izmantojot
vadības paneļa slēdzi, DB ignorēšanas iestatījumu vai `OMNIROUTE_EMERGENCY_FALLBACK`
vides mainīgo —, lai atspējotu šo darbību un ļautu pieprasījumiem ar izsmeltu budžetu
beigties ar kļūdu. (Vadības paneļa slēdža veidā ieviests PR #3741 / #3752.)

Atbildei, kas sniegta, izmantojot šo rezerves mehānismu, ir galvene
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, tādēļ
klients var noteikt, ka pieprasījums tika pārmaršrutēts, nesalīdzinot `X-OmniRoute-Provider` ar savu
pieprasījumu. Visās pārējās atbildēs šīs galvenes nav.
