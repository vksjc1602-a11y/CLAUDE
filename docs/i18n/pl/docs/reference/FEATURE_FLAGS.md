> Przełączniki środowiska wykonawczego, które zmieniają zachowanie OmniRoute **bez ponownego wdrożenia**.
> Każda wymieniona tutaj flaga jest zdefiniowana w pliku
> [`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
> — stanowiącym jedyne źródło prawdy. Zarówno panel, jak i interfejs REST API odczytują dane z
> tego pliku, dlatego poniższa tabela jest generowana tak, aby odpowiadała mu w stosunku 1:1.

---

## Czym są flagi funkcji

Flaga funkcji to nazwany przełącznik (wartość logiczna lub wyliczeniowa), którego wartość można zmieniać w
czasie wykonywania i zapisywać w bazie danych bez konieczności ponownego wdrażania procesu. Każda
flaga jest opisana przez `FeatureFlagDefinition` zawierającą `key`, `label`,
`description`, `category`, `defaultValue`, `type` oraz wskazówkę `requiresRestart`.

### Kolejność rozstrzygania

**Efektywna wartość** flagi jest ustalana przez
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) zgodnie z następującą
kolejnością pierwszeństwa (wyższa pozycja ma pierwszeństwo):

1. **Nadpisanie w bazie danych** — wartość przechowywana w tabeli `key_value` w przestrzeni nazw
   `feature_flags` (ustawiana za pomocą panelu lub interfejsu REST API).
2. **Zmienna środowiskowa** — `process.env[<KEY>]`, jeśli jest ustawiona i nie jest pusta.
3. **Wartość domyślna definicji** — `defaultValue` z pliku `featureFlagDefinitions.ts`.

Flaga logiczna jest uznawana za **włączoną**, gdy jej efektywna wartość to `"true"`,
`"1"` lub `"yes"` (zobacz `isFeatureFlagEnabled()`).

> [!NOTE]
> Większość flag ma również odpowiadającą im zmienną środowiskową o **tej samej nazwie**,
> udokumentowaną w pliku [`ENVIRONMENT.md`](./ENVIRONMENT.md). Nadpisanie flagi w bazie danych
> ma pierwszeństwo przed tą zmienną środowiskową. Flaga z ustawieniem
> `requiresRestart: true` jest zapisywana natychmiast, ale ponownie odczytywana dopiero podczas
> uruchamiania procesu — jej przełączenie powoduje wyświetlenie w panelu banera **„Uruchom serwer ponownie”**.

82 flagi w 6 kategoriach. **Wartość domyślna** oznacza wartość domyślną definicji — używaną,
gdy nie ustawiono ani nadpisania w bazie danych, ani zmiennej środowiskowej.

## Przełączanie flag

### Pulpit nawigacyjny

Przejdź do **Pulpit nawigacyjny → Ustawienia → Flagi funkcji**
(`/dashboard/settings/feature-flags`). Siatka
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
obsługuje:

- **Wyszukiwanie** według klucza lub opisu oraz **filtrowanie** według kategorii (plus syntetyczny
  widok **Wymaga ponownego uruchomienia**).
- **Przełącznik** dla flag logicznych i **rozwijana lista** dla flag wyliczeniowych
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- **Odznakę źródła** dla każdej flagi — `DB`, `ENV` lub `DEF` — pokazującą, skąd pochodzi
  efektywna wartość.
- Przycisk **Resetuj** (pokazywany tylko dla flag pochodzących z `DB`) w celu usunięcia nadpisania
  oraz przycisk **Resetuj wszystkie nadpisania** na dole.
- Baner **Uruchom ponownie serwer**, gdy zmieniona zostanie flaga `requiresRestart`.

### API REST

Wszystkie operacje przechodzą przez jedną trasę:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Każda metoda wymaga uwierzytelnionej sesji pulpitu nawigacyjnego (`401` w przeciwnym razie).

#### `GET /api/settings/feature-flags`

Zwraca każdą flagę z jej efektywną wartością, źródłem i podsumowaniem.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Wymagaj klucza API",
      "description": "Wymagaj klucza API dla wszystkich przychodzących żądań",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... wszystkie 77 flag
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Ustaw lub usuń pojedyncze nadpisanie. Treść: `{ key: string; value?: string }`.
Pominięcie `value` usuwa nadpisanie (przywracając wartość środowiskową / domyślną).

```bash
# Ustaw nadpisanie DB
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Usuń nadpisanie (bez "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Odpowiedź odzwierciedla nową `effectiveValue`/`source`, `previousValue`/
`previousSource` oraz `requiresRestart`. Nieznane klucze i wartości wyliczeniowe spoza zakresu
są odrzucane z `400`.

#### `DELETE /api/settings/feature-flags`

Czyści **wszystkie** nadpisania DB naraz, przywracając każdą flagę do jej wartości środowiskowej / domyślnej.
Zwraca `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Flagi z `requiresRestart: true` wchodzą w życie dopiero po ponownym załadowaniu procesu.
> Przepływ ponownego uruchamiania pulpitu nawigacyjnego wywołuje `POST /api/restart`, a następnie odpytuje
> `GET /api/health/ping` do momentu ponownego uruchomienia serwera.

## Awaryjny mechanizm zastępczy budżetu

`OMNIROUTE_EMERGENCY_FALLBACK` (kategoria `runtime`, domyślnie `true`) kontroluje
awaryjną ścieżkę przełączania na bezpłatną alternatywę w pliku
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Po jej włączeniu żądania, które wyczerpią swój budżet, są kierowane do bezpłatnego
dostawcy/modelu zastępczego zamiast kończyć się niepowodzeniem. Ustaw wartość
`false` (lub `0`) — za pomocą przełącznika w panelu, nadpisania w bazie danych
lub zmiennej środowiskowej `OMNIROUTE_EMERGENCY_FALLBACK` — aby wyłączyć to
zachowanie i pozwolić, by żądania z wyczerpanym budżetem kończyły się
niepowodzeniem. (Udostępniono jako przełącznik w panelu w PR-ach #3741 / #3752).

Odpowiedź obsłużona przez ten mechanizm zastępczy zawiera nagłówek
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`,
dzięki czemu klient może stwierdzić, że żądanie zostało przekierowane, bez
porównywania nagłówka `X-OmniRoute-Provider` z pierwotnym żądaniem. Nagłówek ten
nie występuje w żadnej innej odpowiedzi.
