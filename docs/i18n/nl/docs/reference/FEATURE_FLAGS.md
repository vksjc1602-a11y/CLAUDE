Runtime-schakelaars die het gedrag van OmniRoute wijzigen **zonder een herimplementatie**.
Elke hier vermelde vlag is gedefinieerd in
[`src/shared/constants/featureFlagDefinitions.ts`](../../src/shared/constants/featureFlagDefinitions.ts)
— de enige bron van waarheid. Het dashboard en de REST API lezen beide uit
dat bestand, dus de onderstaande tabel wordt 1:1 gegenereerd om ermee overeen te komen.

---

## Wat Feature Flags Zijn

Een feature flag is een benoemde schakelaar (boolean of enum) waarvan de waarde tijdens runtime kan worden gewijzigd en in de database kan worden opgeslagen, zonder dat een herimplementatie van het proces nodig is. Elke
vlag wordt beschreven door een `FeatureFlagDefinition` met een `key`, `label`,
`description`, `category`, `defaultValue`, `type` en een `requiresRestart`-hint.

### Resolutievolgorde

De **effectieve waarde** van een vlag wordt opgelost door
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) met deze
prioriteit (hoogste wint):

1.  **DB-overschrijving** — een waarde opgeslagen in de `key_value`-tabel onder de
    `feature_flags`-naamruimte (ingesteld via het dashboard of de REST API).
2.  **Omgevingsvariabele** — `process.env[<KEY>]`, indien ingesteld en niet leeg.
3.  **Definitie standaardwaarde** — de `defaultValue` uit `featureFlagDefinitions.ts`.

Een boolean-vlag wordt als **ingeschakeld** beschouwd wanneer de effectieve waarde `"true"`,
`"1"` of `"yes"` is (zie `isFeatureFlagEnabled()`).

> [!NOTE]
> De meeste vlaggen hebben ook een overeenkomstige omgevingsvariabele met **dezelfde naam**,
> gedocumenteerd in [`ENVIRONMENT.md`](./ENVIRONMENT.md). De DB-overschrijving van de vlag
> heeft voorrang op die omgevingsvariabele. Een vlag met
> `requiresRestart: true` wordt onmiddellijk opgeslagen, maar pas opnieuw gelezen bij het
> opstarten van het proces — het schakelen ervan toont een **"Server Herstarten"**-banner in het dashboard.

## Vlaggencatalogus

82 vlaggen verdeeld over 6 categorieën. **Standaardwaarde** is de standaardwaarde van de definitie — de waarde
die wordt gebruikt wanneer er geen database-overschrijving of omgevingsvariabele aanwezig is.

## Vlaggen schakelen

### Dashboard

Navigeer naar **Dashboard → Instellingen → Feature Flags**
(`/dashboard/settings/feature-flags`). Het raster
(`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`)
ondersteunt:

- **Zoeken** op sleutel of beschrijving, en **filteren** op categorie (plus een synthetische
  **Vereist Herstart** weergave).
- Een **schakelaar** voor booleaanse vlaggen en een **dropdown** voor enum-vlaggen
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- Een **bronbadge** per vlag — `DB`, `ENV`, of `DEF` — die aangeeft waar de
  effectieve waarde vandaan kwam.
- Een **Reset**-knop (alleen getoond voor `DB`-bronvlaggen) om de overschrijving te verwijderen,
  en een **Alle Overschrijvingen Resetten**-knop onderaan.
- Een **Server Herstarten**-banner wanneer een `requiresRestart`-vlag wordt gewijzigd.

### REST API

Alle bewerkingen verlopen via één route:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
Elke methode vereist een geauthenticeerde dashboardsessie (`401` anders).

#### `GET /api/settings/feature-flags`

Retourneert elke vlag met zijn effectieve waarde, bron en een samenvatting.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

Stel een enkele overschrijving in of verwijder deze. Body: `{ key: string; value?: string }`.
Het weglaten van `value` verwijdert de overschrijving (herstel van env / default).

```bash
# Stel een DB-overschrijving in
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Verwijder de overschrijving (geen "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

Het antwoord herhaalt de nieuwe `effectiveValue`/`source`, de `previousValue`/
`previousSource`, en `requiresRestart`. Onbekende sleutels en enum-waarden buiten bereik
worden afgewezen met `400`.

#### `DELETE /api/settings/feature-flags`

Wist **alle** DB-overschrijvingen in één keer, waardoor elke vlag wordt hersteld naar zijn env / standaard
waarde. Retourneert `{ cleared: <count>, message: "..." }`.

> [!NOTE]
> Vlaggen met `requiresRestart: true` worden pas van kracht na een procesherlading.
> De herstartstroom van het dashboard roept `POST /api/restart` aan en peilt vervolgens
> `GET /api/health/ping` totdat de server weer actief is.

## Noodfallback voor budget

`OMNIROUTE_EMERGENCY_FALLBACK` (categorie `runtime`, standaardwaarde `true`) regelt het
gratis noodfallbackpad in
[`open-sse/services/emergencyFallback.ts`](../../open-sse/services/emergencyFallback.ts).
Wanneer dit is ingeschakeld, worden aanvragen waarvan het budget is uitgeput, doorgestuurd naar een
gratis fallbackprovider/-model in plaats van direct te mislukken. Stel dit in op `false` (of `0`) — via de
schakelaar op het dashboard, een DB-override of de omgevingsvariabele
`OMNIROUTE_EMERGENCY_FALLBACK` — om dit gedrag uit te schakelen en aanvragen
waarvan het budget is uitgeput te laten mislukken. (Beschikbaar als dashboardschakelaar in PR's #3741 / #3752.)

Een respons die door deze fallback wordt geleverd, bevat
`X-OmniRoute-Emergency-Fallback: from=<provider/model>; to=<provider/model>`, zodat een
client kan zien dat deze is omgeleid zonder `X-OmniRoute-Provider` met zijn
aanvraag te vergelijken. Bij alle andere responsen ontbreekt deze header.
